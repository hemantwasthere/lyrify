# Full Layout's backdrop becomes a color-extraction wash, not a blur

ADR-0009 approximated Spotify Mini Player's backdrop with a strong Gaussian blur plus a saturation boost (`CoreImageArtworkBlur`) — a smeared, still-recognizably-shaped copy of the artwork itself. A full set of Spotify Mini Player reference screenshots shows this isn't what Spotify actually renders: none of them show blurred shapes at all, even behind visually busy source artwork (a detailed multi-color illustration renders as a flat, uniform gray-lavender backdrop — a blur of that image would show blotchy color regions following the illustration's own composition, not a uniform wash). What Spotify renders is a dominant/average color sampled from the artwork, applied as a flat or very subtly gradiented wash. `CoreImageArtworkBlur` is replaced with a color-extraction implementation of the same `ArtworkBlurring` seam.

## Consequences

The `ArtworkBlurring` protocol's shape (`func blur(_ artwork: Data) async -> Data?`, an injected seam off `BlurredArtworkProvider`) is unchanged — only its production implementation changes, from a CoreImage Gaussian blur to a CoreImage-based dominant/average color sampler that renders a flat or gently-gradiented wash the same pixel dimensions as the source artwork. `BlurredArtworkProvider`'s own actor, memoization, and Track-URI-keyed dedup logic are unaffected — a pure function of the same artwork bytes either way.

The feature's own naming — `BlurredBackgroundPreference`, the "Blurred Background" toggle label, `updateBlurredBackground`/`fullArtworkBackgroundView` — no longer describes what it does; a blur that produces no blurred shapes is a misnomer future readers would trip over. The Settings Face toggle is relabeled "Background color," matching Spotify's own Mini Player settings panel exactly; renaming the underlying types/methods to match is left to implementation, not fixed by this ADR.

`CoreImageArtworkBlur`'s existing tests (`CoreImageArtworkBlurTests.swift`) exercised blur-radius and saturation-boost behavior specifically; a replacement implementation needs its own tests for color-extraction behavior (e.g., a solid-color source resolves to that same color; a multi-color source resolves to some deterministic dominant/average, not an arbitrary pixel sample) rather than reusing the old assertions.
